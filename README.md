# سرویسا (Care+) — بسته کامل طراحی و واگذاری پلتفرم خدمات آنلاین

بسته‌ای برای واگذاری کار به پیمانکار یا تیم داخلی: از سند نیازمندی و معماری تا **کد اجرایی، مدل داده،
کاتالوگ API، نمونه اولیه کلیک‌پذیر، PDF رسمی و تحلیل عمیق ماژول تخصیص**.

## ۳) بازتولید کل بسته

```bash
# ۱) سند HTML
python3 spec/_build/build.py

# ۲) واژه‌نامه و برآورد (بر پایه فهرست واحد جداول)
python3 tools/generate_planning_assets.py

# ۳) PDFها  (نیازمند Chromium/Playwright — بخش ۶)
python3 tools/build_pdf.py spec/index.html pdf/care-plus-spec.pdf \
        --title "سند جامع سرویسا (Care+) — نسخه ۱.۰" --toc 3
python3 tools/build_pdf.py analysis/dispatch-deep-dive.html \
        pdf/care-plus-dispatch-deep-dive.pdf --title "تحلیل عمیق موتور تخصیص سرویسا" --toc 2

# ۴) تحلیل تخصیص
python3 tools/dispatch_sim.py            # شبیه‌سازی + نمودار + CSV
python3 tools/golden_cases.py            # سناریوهای طلایی (fixure رگرسیون)
python3 tools/build_dispatch_report.py   # ساخت HTML گزارش از نتایج

# ۵) MVP
cd mvp && pip install -r requirements.txt
python3 demo.py accept                    # دموی خط فرمان
python3 -m uvicorn app.main:app --port 8000   # کنسول دمو روی http://localhost:8000/
python3 -m pytest tests -q                # ۱۵ آزمون
```

## ۴) اسکلت اجرایی MVP — `mvp/`

پیاده‌سازی مرجع سه ستون اصلی سند: **قیمت‌گذاری شفاف، Escrow چندمرحله‌ای، تخصیص امتیازمحور**.
جزئیات کامل در `mvp/README.md`. خلاصه:

- **`PricingService`** — تعرفه نسخه‌دار × ضریب فوریت (۰.۹۵–۱.۳۵) × ضریب پیچیدگی + ضریب تقاضای منطقه
  (سقف ۱.۵، معاف برای خدمات امدادی) + ایاب‌وذهاب + اقلام، با **تفکیک ردیف‌به‌ردیف** و نسخه موتور قیمت.
- **`DispatchService`** — همان ۹ وزن سند، فیلترهای سخت (فاصله/مهارت/تجهیز حیاتی/ظرفیت/انسداد)،
  موج ۳ پیشنهاد با TTL ۹۰ ثانیه (فوری ۲۰ ثانیه)، حداکثر ۳ موج، نردبان تشدید و **پذیرش اتمی**؛
  هر پیشنهاد با متن «چرا این پیشنهاد برای شما» به متخصص نمایش داده می‌شود.
- **`LedgerService`** — دفتر کل دوعاملی **زنجیره‌ای با هش** (هر قید امضای قید قبلی): مشتری → Escrow →
  کمیسیون/بیمه/مالیات → کیف پول متخصص، با بازگشت وجه، تراز آزمایشی و تراکنش‌های ابطال‌پذیر.
- **`ReviewService`** — امتیاز پنج‌بعدی و رتبه‌ی نمایشی بیزی (پیش‌فرض ۳.۹، m=۱۰).
- **تعامل:** `POST /v1/orders` با `Idempotency-Key`، ۵۱ مسیر REST، رویدادها در `event_outbox` (نماینده Kafka)،
  کنسول دمو روی `/` با روایت گام‌به‌گام، شاخص‌ها، تراز دفتر کل و مرورگر رویدادها.

## ۵) تحلیل عمیق موتور تخصیص — `analysis/`

گزارش ۱۱ صفحه‌ای که با داده بازتولیدپذیر به این پرسش‌ها پاسخ می‌دهد: راهبرد امتیازمحور چه اندازه
بر «نزدیک‌ترین متخصص» و «صف سنتی» برتری دارد؟ هر وزن چقدر اثر دارد؟ نردبان تشدید چقدر می‌ارزد؟
Surge چه می‌کند؟ عدالت توزیع چه اثری بر ریزش عرضه دارد؟

یافته‌های کلیدی (اعداد از `analysis/dispatch_sim_results.json`، ۱٬۹۰۰ سفارش / ۲۶۰ متخصص):

- **گلوگاه، ظرفیت عرضه است نه فرمول:** در عرضه عادی هر سه راهبرد بالای ۹۲٪ تخصیص می‌دهند؛
  در کمبود عرضه (۴۵٪ آنلاین) همه به ۶۰٪ سقوط می‌کنند.
- **نردبان تشدید، مؤثرترین اهرم:** حذف آن ⇒ افت ۸.۵ واحد درصدی نرخ تخصیص و جهش ارجاع به اپراتور.
- **ترتیب بهینه نردبان: «شعاع → شعاع+انگیزه → انگیزه بیشتر → اپراتور»**؛ گسترش شعاع پیش از پرداخت
  انگیزه، ارزان‌تر است (صرفه‌جویی حدود ۲۹ میلیون ریال انگیزه در نمونه).
- **±۵۰٪ تغییر وزن‌ها، کمتر از ۱ واحد درصد** نرخ تخصیص را جابه‌جا می‌کند ⇒ کالیبراسیون وزن‌ها
  توجیه تأخیر راه‌اندازی نیست؛ وزن عدالت (۰.۰۴→۰.۱۰) اهرم **نگهداشت عرضه** است.
- **سناریوهای طلایی** (`analysis/golden_dispatch_cases.json`): ۶ سفارش کنترل‌شده با رتبه‌بندی کامل
  و تطابق تأییدشده شبیه‌ساز/سرویس — آماده به‌کارگیری به‌عنوان آزمون رگرسیون.

## ۶) ابزارها و پیش‌نیازها

| ابزار | کارکرد |
|---|---|
| `tools/build_pdf.py` | تبدیل HTML فارسی به PDF با Chromium/Playwright (جلد، سرصفحه، فونت جاسازی‌شده) |
| `tools/dispatch_sim.py` | شبیه‌ساز موتور تخصیص + ۵ سناریو + نمودار/CSV/JSON |
| `tools/golden_cases.py` | ساخت مجموعه سناریوهای طلایی از دل سرویس اجرایی |
| `tools/build_dispatch_report.py` | ساخت گزارش HTML خودبسنده از نتایج شبیه‌سازی |
| `tools/generate_planning_assets.py` | واژه‌نامه داده + برآورد RFP از یک منبع |
| `tools/install_chromium_deps.py` | نصب کتابخانه‌های سیستمی Chromium بدون دسترسی root |

پیش‌نیاز PDF (یک‌بار در هر محیط تازه):
```bash
pip install playwright && python3 -m playwright install chromium
python3 tools/install_chromium_deps.py          # استخراج libها در ~/.cache/chromium-libs
# اجرای هر اسکریپت Playwright با:
export LD_LIBRARY_PATH=~/.cache/chromium-libs:$LD_LIBRARY_PATH
```
> پوشه‌های `~/.cache/*` در snapshot محیط ذخیره نمی‌شوند؛ در نشست بعدی دوباره ساخته می‌شوند.

## ۷) فرض‌ها و محدودیت‌ها

- همه برآوردهای زمان/هزینه **برنامه‌ریزی‌محور** و نیازمند تأیید بازار؛ نرخ‌ها باید با پیمانکار نهایی شود.
- MVP با SQLite اجرا می‌شود؛ نقشه انتقال به PostgreSQL/PostGIS + Kafka + Redis GEO در `mvp/README.md` آمده است.
- مدل پذیرش متخصص در شبیه‌ساز **ساختاری و کالیبره‌نشده** است؛ اعداد تحلیل «جهت‌نما» هستند و در فاز پایلوت
  باید با داده واقعی پیشنهاد/پاسخ بازبرآورد شوند (طرح A/B در گزارش بخش ۴ آمده است).
- پیش از راه‌اندازی Escrow، BNPL و کار با داده هویتی، **بازبینی حقوقی مستقل** ضروری است (ریسک‌های R-01…R-12).
